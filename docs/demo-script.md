# Four-minute local demonstration

Use separate browser profiles for buyer, seller and moderator. Read randomly generated access from `.local/demo-access.json`; never put passwords in recordings. Start app, services and worker using the README. All examples are fictional.

1. **0:00–0:40 — The sourcing problem.** Show the home page and search `RC-1600`. Explain leftover boxes, precise model/batch details and approximate pickup area. Switch to Bangla, then back. Compare compatible tiles and adjust the coverage calculator; point out unknown specifications rather than assuming matches.
2. **0:40–1:30 — Seller to public listing.** As seller, create eight boxes of tiles with a local photo, batch/code, quantity and price. Submit. As moderator, inspect disclosures/photos and approve with a reason. Return to public search. Explain that later material edits trigger another review.
3. **1:30–2:45 — Three boxes, correct inventory.** As buyer, request three boxes. Show that pending requests do not reserve stock. Seller accepts, shows the 24-hour hold and marks ready. Both parties explicitly confirm physical handover. Show five remaining boxes and the buyer's eligible review. Cash receipt is recorded separately; the platform did not hold buyer funds.
4. **2:45–3:25 — Matching and safety.** Show a wanted request, possible matches with unknown fields, a seller response, private messages and a report. Open moderator audit controls. Explain participant authorization rather than implying identity/material certification.
5. **3:25–4:00 — Engineering evidence.** Open testing.md, inventory concurrency tests and performance summary. Explain row locks, idempotent transitions and worker-delayed expiry. Optional: demonstrate clearly labelled promotion simulator. End with credential/deployment gaps in launch-readiness.md.

Keep developer documentation separate from the customer storefront. Avoid presenting seeded sales/reviews as genuine business results.
